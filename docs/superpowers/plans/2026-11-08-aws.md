# AWS Deployment Templates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `aws/` with ported single-instance and new 3-node HA templates (Terraform and CloudFormation), static CI, and a live deploy test in the private `arcadedb-ami` repo.

**Architecture:** Flat, independent templates per topology and tool (no shared modules, repo showcase style). HA = 3 EC2 nodes in 3 AZs, discovered through a Route 53 private zone, optional internal NLB on 2480. Public CI validates statically; `arcadedb-ami` deploys, smoke-tests and destroys.

**Tech Stack:** Terraform >= 1.0 (AWS provider), CloudFormation, GitHub Actions, `cfn-lint`, AWS SSM Run Command (tests).

**Spec:** `docs/superpowers/specs/2026-11-08-aws-design.md`

## Global Constraints

- Layout: `aws/terraform/{single-instance,ha-cluster}/`, `aws/cloudformation/{single-instance,ha-cluster}.yaml` + `aws/cloudformation/README.md`, `aws/README.md`, `.github/workflows/aws.yml`.
- Do NOT port `ci-github-oidc-role.yaml`; no references to Packer names, `ManagedBy: packer-arcadedb-ami`, or private-repo docs/links.
- HA node names `node-0`..`node-2` (0-based numeric suffix required); Raft port 2434, HTTP 2480.
- ArcadeDB settings via the existing `ARCADEDB_SETTINGS` systemd override: `-Darcadedb.server.name`, `-Darcadedb.ha.enabled=true`, `-Darcadedb.ha.serverList=node-N.<zone>:2434:2480,...`, `-Darcadedb.ha.replicationFactor=3`, `-Darcadedb.server.readinessRequiresHA=true`, `-Darcadedb.server.rootPassword`.
- Defaults safe: EBS encrypted gp3, IMDSv2 required, `allowed_cidr` never defaults to `0.0.0.0/0`, public IPs off by default in HA.
- Private zone default `arcadedb.internal`; NLB toggle default on; root password is a sensitive variable / `NoEcho` parameter, no Secrets Manager.
- CloudFormation takes an `AmiId` parameter; Terraform keeps `ami_id` / `marketplace_product_code` lookup.
- Action pins match existing workflows (e.g. `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`, `hashicorp/setup-terraform@dfe3c3f87815947d99a8997f908cb6525fc44e9e # v4.0.1`).
- Repo style: readability over DRY; branch `feat/aws`.

## Review Focus

- Root password containing characters outside `A-Z a-z 0-9 @ ! # ^ + = . _ & -`: rejected by validation (source rule), not silently accepted.
- Subnets not in three distinct AZs: Terraform plan fails with a clear message.
- `allowed_cidr = 0.0.0.0/0`: not the default; README warns.
- arm64 instance type with an x86_64 AMI (or the reverse): fails at AMI lookup/validation, not at launch.
- NLB disabled: outputs and Studio URL still valid (fall back to `node-0`).
